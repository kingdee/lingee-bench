# 运行与评分约定

## 题集

企业管理题集包含财务、制造、供应链30题，通用题集包含35题，分别报告成绩。示例任务（`examples/tasks`）只用于安装、框架自测与调试。具体题目以各题集清单为准，任务版本在`task.toml`中记录。

题面、业务输入和评分资产随题集在Hugging Face发布，评测框架在本仓库。Agent运行时只接收题面和环境输入，`tests/`及答案只在验证阶段装载。公开评分资产不表示允许Agent在解题过程中读取它们。

## 执行

Harbor负责容器、调度、超时、轨迹、产物和清理。各harness通过相同任务与评分器运行；比较时固定模型、预算、输入、轮次和评分版本。

模型请求通过每个trial的模型代理发送。ERP任务经MCP代理访问冻结业务快照，工具白名单与数据集由逐题Job声明。真实ERP连接仅用于联调，不作为公开复现的必要条件。

通用任务使用正式Job声明的Docker内部网络与模型代理。直接绕过Job只传`--path`不能保证相同网络边界。

## 评分

ERP内容与数值分别评分；数值字段、业务键、单位、精度、缺失及冲突规则以题面和评分配置为准。通用任务按各题规则通道与Judge rubric合分。不得根据某个Agent的得分临时改规则、替换输入或调整权重。

评分只使用本题授权的最终结果和证据。格式检查不能代替业务正确性，Agent自报完成不能代替实际交付。Judge连接或协议故障属于评测故障，不作为合法业务零分。

## 成绩报告

报告分别列出题集、Git版本、任务及输入版本、harness版本、Agent和Judge模型、运行次数、预算、有效覆盖率及故障数。正常评分才计入成绩均值，缺失评分和基础设施异常单独列出。

使用公开题调参、few-shot、训练或逐题分析时需披露；公开集成绩不代表未见任务泛化表现。保留集应由独立托管环境执行，不能与公开集混成一个未经说明的总分。

## 边界

当前任务验证模式包含与Agent共用容器的verifier。文件摘要可检测输入变化，但不构成对恶意Agent的完整防篡改边界；受控榜单运行应采用独立可信验证环境。

任务输入、模型调用和评测日志分别管理。凭据、会话原始日志、内部源材料和临时交付包不进入公开版本。第三方组件与素材的原有通知和许可保持独立。
